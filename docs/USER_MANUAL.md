# kiw_soxl_trader 사용자 매뉴얼 v1.0

키움증권 해외주식 SOXL 스나이퍼 자동매매 봇 · 서비스명 `kiwoombot_soxl` · 로그 프리픽스 `[SOXL]`

---

## 0. 한눈에 보기

- **무엇인가**: 토스증권용 「인피니트 스노우볼 v3.0」(pipios, SOXL 7층 그리드 스나이퍼)을 **키움증권 REST API(미국주식)** 로 돌릴 수 있게 만든 프로그램입니다.
- **핵심 설계**: 원본 소스 15개는 `engine/` 폴더에 **받은 그대로** 둡니다. 원본이 토스 서버로 보내는 통신만 키움으로 바꿔 끼웁니다. 그래서 원본이 바뀌면 **새 zip 을 올리고 `sync_kiw_soxl` 한 번**이면 됩니다.
- **매매 판단은 원본 엔진이 합니다.** 8% 정량, 7층 그리드, 익절 %, 매수 게이트, 예비시드 등 전략 수치는 원본 소스에 있고 이 프로그램은 바꾸지 않습니다. 이 프로그램이 더한 것은 ① 키움 연결 ② 매매 기록 ③ 일·주·월 보고(텔레그램·이메일) ④ 버튼 메뉴 ⑤ 안전장치입니다.
- **반드시 순서대로**: `DRY_RUN(가상 체결)` → `모의투자(MOCK)` → `실전(REAL) 소액`. 아래 **3장 "실거래 전 확인 5가지"** 를 건너뛰지 마세요.

### 키움 연결 블록이 하는 일

원본 엔진은 토스 주소와 토스 응답 모양만 압니다. 엔진의 모든 통신은 `TossApiClient._request` 한 함수를 거치는데, 이 함수를 `toss_bridge.TossBridge.request` 로 바꿔 끼웁니다.

| 엔진이 부르는 토스 주소 | 키움 TR | 비고 |
|---|---|---|
| GET /api/v1/prices | usa20100 현재가 | SOXL 0.35초, QQQ 5초 캐시 |
| GET /api/v1/orderbook | usa20101 10호가 | |
| GET /api/v1/trades | usa20150 상세 체결내역 | 시각 형식이 다르면 자동으로 무시 |
| GET /api/v1/candles | usa06011 분 차트 / usa06012 일 차트 | 시간대 자동 판정 |
| GET /api/v1/exchange-rate | ust31301 환율 | 실패 시 현재가 응답의 환율 |
| GET /api/v1/holdings · sellable-quantity | ust21070 원장잔고확인 | |
| GET /api/v1/buying-power | ust21110 해외주식 예수금(외화주문가능금액) | 상한 설정 가능 |
| POST /api/v1/orders | ust20000 매수 / ust20001 매도 | 지정가(00)만 |
| POST …/modify · …/cancel | ust20002 정정 / ust20003 취소 | |
| GET /api/v1/orders/{id} · /orders?status= | ust21510 당일 주문체결 · ust21150 일별 · ust21050 미체결 | |
| GET /api/v1/commissions | (config.json 의 수수료율) | 키움에 해당 조회 없음 |
| GET /api/v1/accounts · market-calendar/US | (고정 응답 / 빈 값) | 엔진은 자체 요일·시간 판정 사용 |

TR ID 와 필드명은 키움증권 공식 저장소(Kiwoom-Securities/Kiwoom-REST-API, 2026-09-15 커밋)의 명세를 따랐습니다.

## 2. 설치

1. PC의 `Source/kiw_soxl_trader_v1.0.0_full.zip` 과 `Scripts/setup_kiw_soxl_trader.sh` 를 서버 홈(`~`)에 올립니다. **zip 은 풀지 않습니다** (다른 키움 봇과 파일 이름이 겹치지 않게).
2. `bash ~/setup_kiw_soxl_trader.sh`
3. `nano ~/kiw_soxl_trader/.env` 에서 키움 키·계좌, 텔레그램 토큰·chat_id 입력.
   - 텔레그램 봇은 **다른 봇과 다른 새 봇**(BotFather)으로 발급하세요. 한 토큰을 두 프로그램이 쓰면 서로 메시지를 빼앗습니다.
   - 처음에는 `TRADE_MODE=MOCK`, `DRY_RUN=true`.
4. `cd ~/kiw_soxl_trader && kiw_soxl_venv/bin/python3 diag.py` → 끝의 "권장 설정"을 반영.
5. `deploy_kiw_soxl` 로 기동. 텔레그램에 "✅ 서버가 정상 작동 중입니다." 가 오면 성공.

| 명령 | 하는 일 |
|---|---|
| `deploy_kiw_soxl` | 홈의 `kiw_soxl_trader_v*_update.zip` 반영 → 점검 → 재시작 (zip 없으면 점검·재시작만) |
| `sync_kiw_soxl` | 홈의 새 원본 zip(`pipiosToss_bot-main.zip`)에서 바뀐 파일만 `engine/` 에 반영 + 호환성 점검 |
| `sync_kiw_soxl check` / `rollback` | 현재 원본 점검 / 직전 원본으로 되돌리기 |
| `stop_kiw_soxl` (`--permanent`, `--status`) | 중지 / 영구 중지 / 상태 보기 |

## 3. 실거래 전 확인 5가지 (중요)

키움 명세서만으로는 확정할 수 없어 **실제 계좌 응답으로 확인해야 하는 항목**입니다. `diag.py` 가 대부분 찍어 줍니다.

| # | 확인할 것 | 방법 | 문제가 있으면 |
|---|---|---|---|
| 1 | **프리장(04:00~09:30 ET) 지정가 주문이 REST API 로 접수되는가** | 프리장 시간에 `python3 diag.py --order-test` (1주를 현재가의 절반 가격에 주문 후 즉시 취소) | 접수가 안 되면 이 전략의 프리장 구간은 키움에서 쓸 수 없습니다. 정규장만으로는 원본 백테스트와 결과가 달라집니다. |
| 2 | **1분봉에 프리장 봉이 들어오는가, 시각이 미국 동부시간인가** | `diag.py` 5번 항목 | `KIWOOM.CHART_TZ` 를 ET/KST 로 고정. 봉 시각이 '끝 시각'이면 `KIWOOM.CANDLE_TIME_IS_END=true` |
| 3 | **당일 주문조회(ust21510) 필드** — 주문잔량·체결수량이 주문 1건당 1행으로 오는가 | `diag.py --order-test` 의 "취소 후 행" | 필드명이 다르면 `toss_bridge._summarize` 한 곳 보정 |
| 4 | **수수료율** | 영웅문/키움 홈페이지에서 본인 계좌의 미국주식 수수료율 확인 | `FEE.US_COMMISSION_RATE` 에 입력 (엔진의 순익·익절 하한 계산에 쓰임. 엔진 허용 범위 편도 1% 이하) |
| 5 | **같은 계좌에 다른 달러가 있는가** | 📋 키움 메뉴 → 💼 계좌잔고의 "봇 몫이 아닌 주문가능 달러" | `SAFETY.MAX_BOT_BUYING_POWER_USD` 로 봇이 볼 수 있는 달러 상한 지정 |

5번 설명: 원본 엔진은 시드가 바닥나면 계좌에 남아 있는 달러를 예비시드로 **자동 수혈**합니다. 원본 매뉴얼에는 "최대 +6회분"으로 적혀 있지만, 받은 소스의 상수는 `MAX_RESERVE_PORTIONS = 999999` (사실상 무제한)입니다. 계좌에 다른 용도의 달러가 있거나 원화 통합증거금으로 주문가능금액이 크게 잡히면 봇이 그 돈까지 쓸 수 있으므로 상한을 정해 두는 것이 안전합니다.

### 권장 진행 순서

1. **DRY_RUN=true (1~2주)**: 시세·차트는 키움에서 실제로 받고, 주문만 봇 내부 가상 계좌에서 체결시킵니다(매수는 현재가가 지정가 이하, 매도는 지정가 이상일 때 지정가로 전량 체결). 원장은 `run/dry` 에 따로 저장됩니다.
2. **TRADE_MODE=MOCK, DRY_RUN=false**: 키움 모의투자 서버로 실제 주문 경로를 확인합니다. 원장은 `run/mock`.
3. **TRADE_MODE=REAL, DRY_RUN=false**: 작은 시드로 시작합니다(⚙️ 전술 제어반 → 💵 기준 시드머니). 원장은 `run/real`.

모드를 바꾸면 원장이 서로 섞이지 않고 각 폴더의 것을 씁니다. 실전 계좌에 이미 SOXL 을 들고 있는 상태로 처음 켜면 엔진이 그 수량을 "수동 매수"로 보고 지층에 편입합니다(원본 동작).

## 4. 설정

### .env (비밀값, 바꾸면 재시작)
`TRADE_MODE`, `KIWOOM_APP_KEY(_MOCK)`, `KIWOOM_SECRET_KEY(_MOCK)`, `KIWOOM_ACCOUNT_NO(_MOCK)`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SMTP_*`, `EMAIL_TO`, `DRY_RUN`, `BOT_LABEL`, `LOG_LEVEL`

### config.json (저장 즉시 반영 — 텔레그램 🛠 설정 또는 `/set 키 값`)

| 분야 | 키 | 기본값 | 뜻 |
|---|---|---|---|
| 수수료 | `FEE.US_COMMISSION_RATE` | 0.0025 | 편도 수수료율(0.25%). **본인 계좌 값으로 수정** |
| 안전 | `SAFETY.MAX_BOT_BUYING_POWER_USD` | 0 | 봇에 보여줄 주문가능 달러 상한 (0=제한 없음) |
| 안전 | `SAFETY.MAX_ORDER_USD` | 0 | 1회 매수 주문 상한 (0=제한 없음, 초과 주문은 거부) |
| 안전 | `SAFETY.ALLOW_ENGINE_GIT_UPDATE` | false | 원본의 깃 자동 업데이트 허용 여부 (false 유지 권장) |
| 안전 | `SAFETY.DRY_RUN_START_CASH_USD` | 10000 | 가상 계좌 시작 금액 |
| 종목 | `SYMBOLS.SOXL / SGOV / QQQ` | AUTO | 키움 거래소구분(NA/ND/NY). diag 결과로 고정 가능 |
| 키움 | `KIWOOM.CHART_TZ` | AUTO | 분봉 시간대 (AUTO/ET/KST) |
| 키움 | `KIWOOM.QUERY_MIN_INTERVAL` | 0.22 | 조회 최소 간격(초) |
| 보고 | `REPORT.DAILY_TIME_KST` 등 | 07:10 | 일간(화~토) · 주간(토 07:20) · 월간(1일 07:30) |
| 이메일 | `EMAIL.ENABLED / DAILY / WEEKLY / MONTHLY / ATTACH_EXCEL` | | 📧 이메일보고 버튼으로 전환 |
| 알림 | `ALERT.API_ERROR`, `ALERT.FILL`, `ALERT.STALE_CANDLE_MIN` | | 키움 오류·분봉 지연 알림 |

작동 ON/OFF, 기준 시드, 운용 모드(복리/단리/바벨), 암살자 모드는 **원본 화면(⚙️ 전술 제어반)** 에서 바꿉니다.

## 6. 매매 기록과 보고

### 기록 (data/kiw_soxl_journal.db)

| 표 | 내용 |
|---|---|
| orders | 봇이 낸 모든 주문: 키움 주문번호, 가격·수량, 상태, 정정/취소 연결 |
| fills | 체결 건별 + **그 순간의 상황**: 현재가, 층수와 각 층 단가, 기준가, 기억저가, 가용현금, 엔진 주문유형(예: REENTRY_1FL, DIP_1FL, SELL_L1_ONLY), 지표(RSI·VWAP 등) |
| ledger_ev | 원본 엔진 원장의 변화: 매수/매도 횟수, **실현손익 증가분**, 싸이클 졸업, 스텝업 해금, 예비시드 수혈·상환, 작동 ON/OFF·모드·시드 변경 |
| snapshots | 10분 간격(미국 장 시간) 계좌·지층 스냅샷 → 자산 추이 |
| events | 엔진 알림 전문, API 오류, 설정 변경, 보고 발송 |

## 7. 원본 소스가 바뀌었을 때

1. 새 `pipiosToss_bot-main.zip` 을 서버 홈에 올립니다.
2. `sync_kiw_soxl` — 무엇이 바뀌었는지 보여 주고(파일별 +/- 줄 수), 미리 점검한 뒤 반영 여부를 묻습니다.
3. 점검 통과 → 바뀐 파일만 `engine/` 에 복사, 이전 것은 `data/engine_backups/` 에 보관 → 재시작.

점검 항목: 필수 모듈 존재 · 문법 · **엔진이 쓰는 토스 주소가 모두 브릿지에 있는지** · 연결 고리 이름(9개) 존재 · 새 외부 패키지 · 주요 상수 변화(시드, 수수료 기본값, 예비시드 한도, 루프 주기 등).

- 대부분의 원본 변경(전략·지표·알림·화면)은 **키움 블록 수정 없이** 그대로 반영됩니다.
- `❌ 브릿지에 없는 토스 주소` 가 나오면 원본이 새 토스 기능을 쓰기 시작한 것입니다. 이때만 `toss_bridge.py` 의 `ROUTES` 에 한 줄과 처리 함수 하나를 더하면 됩니다. 출력 내용을 Claude 에게 보여 주면 됩니다.
- `❌ 연결 고리 대상 없음` 은 원본이 텔레그램·업데이트 구조를 바꾼 경우이며 `engine_hooks.py` 의 `HOOK_TARGETS` 를 맞춥니다.
- 문제가 생기면 `sync_kiw_soxl rollback`.

## 9. 알아둘 제한

- **수익을 보장하지 않습니다.** 원본의 "5년 승률 100%"는 원본 작성자의 백테스트 결과이며 이 포팅에서 재검증하지 않았습니다. SOXL 은 3배 레버리지 ETF 이고 이 전략은 손절이 없어, 장기 하락 시 자금이 묶이고 평가손실이 커질 수 있습니다.
- 통합 테스트는 **가짜 키움 서버**(tests/fake_kiwoom.py)로 했습니다. 엔진 기동 → 1층 매수 → 60초 뒤 +1.5% 익절 → 0주 졸업까지 원본 엔진이 실제로 돌았고 기록·보고가 맞게 남는 것을 확인했습니다. **실제 키움 서버 응답으로는 아직 확인하지 않았습니다** (3장).
- 키움 미국주식 API 호출 제한은 공개 자료 기준 조회 초당 5회(혼잡 시간 3회)·주문 초당 10회입니다. 시험 중 측정값은 분당 약 170회(초당 3회 미만)였습니다. 키움 공지로 최신 값을 확인하세요.
- 주간거래(데이마켓)·애프터장 매수는 원본이 쓰지 않습니다.
- 봇을 멈춰도 키움에 나가 있는 미체결 주문은 남습니다.
